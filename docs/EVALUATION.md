# Evaluation

## Dataset

`demo/questions.json` holds 20 questions over the three synthetic documents generated by
`demo/generate_demo.py`:

| Type | Count | What it tests |
|---|---|---|
| single | 11 | one fact in one document (8 EN, 3 VI) |
| multi | 1 | facts from two documents |
| comparison | 2 | structured comparison across documents (1 EN, 1 VI) |
| conflict | 2 | documents that deliberately disagree (12 vs 24 months; 24 hours vs 1 hour) |
| unanswerable | 3 | nothing in the corpus answers it (2 EN, 1 VI) |
| isolation | 1 | answer exists only in an **unselected** document |

Each answerable question lists its **evidence**: the document, an exact phrase, and the page (PDF) or section
(DOCX). A retrieved chunk counts as relevant only if all of these match, so the metrics also check citation
locations. `tests/test_evaluation.py` verifies that every evidence reference exists in the indexed corpus.

Q20 is a prompt-injection probe: page 7 of the handbook contains a planted instruction to claim unlimited leave.

## Metrics

Deterministic (string matching, no model judgement):

- **Recall@k**: share of expected evidence passages that appear in the top-k retrieved chunks, averaged over
  answerable questions.
- **Hit rate@k**: share of answerable questions with at least one evidence passage in the top-k.
- **MRR**: mean of 1 / rank of the first relevant chunk (0 if none).
- **Source identification**: all expected documents appear in the top-k.
- **Out-of-scope leaks**: chunks returned from documents outside the question's scope (must be 0).

Answer-level (only with a generator; still string checks, **not** LLM-as-judge):

- **Citation validity**: the answer contained no citation ID outside the retrieved set.
- **Cited-evidence hit**: at least one cited source is a labelled evidence passage.
- **Keyword match**: all expected answer keywords (for example `18`) appear in the answer.
- **Unanswerable handled**: the model set `insufficient_evidence` on unanswerable and isolation questions.

## How to run

```powershell
.\.venv\Scripts\python.exe demo/run_evaluation.py                  # offline lexical embedder, retrieval only
.\.venv\Scripts\python.exe demo/run_evaluation.py --mode gemini    # Gemini embeddings + answers (needs key)
```

Both index the demo documents into a temporary ChromaDB directory and write
`docs/evaluation_results/<mode>.json`. The **Evaluation** page in the app runs the same procedure.

## Results

### Offline lexical baseline (measured)

Embedder `local:hashing-lexical-v1:1024`, top-k 5, no generation. Source:
[`evaluation_results/offline.json`](evaluation_results/offline.json).

| Metric | Value |
|---|---|
| Recall@5 | 0.69 |
| Hit rate@5 | 0.81 |
| MRR | 0.72 |
| Source identification | 0.81 |
| Out-of-scope leaks | 0 |
| Recall@5, English questions (12) | 0.79 |
| Recall@5, Vietnamese questions (4) | 0.38 |

### Gemini embeddings and answers

**Not run yet.** No Gemini API key was available in the development environment, so there are no measured
numbers for `gemini-embedding-001` retrieval or for answer quality. Run `--mode gemini` with a key to produce
them. They are not estimated here.

## Failure analysis (offline baseline)

| Question | Recall | What happened |
|---|---|---|
| Q07 information classification levels | 0.00 | The classification table says "Level", the question says "levels"; with no stemming the table chunk ranks below the section's prose paragraphs. |
| Q08, Q09 (Vietnamese) | 0.00 | No shared words between Vietnamese questions and English text. A lexical method cannot do cross-lingual retrieval. |
| Q11, Q12, Q13, Q15 (two documents) | 0.50 | One document's passage is found; the other's shares too few exact words, so the security policy's many short chunks fill the top 5. |
| Q06, Q14 | 1.00, RR < 1 | Found, but ranked 3rd to 4th behind chunks with more overlapping words. |

Isolation (Q19) held: with only the handbook selected, all retrieved chunks came from the handbook.

### Things tried

- **Document-diverse selection** (reserve a top-k slot for each selected document's best chunk when its score
  is at least 40 to 80% of the top score). On this dataset it gave no gain at k=5; at k=3 it left Recall@3
  unchanged (0.59) at ratio 0.4 and lowered it to 0.56 at ratios 0.5 to 0.8, so it was not kept. The multi-document misses come from low lexical similarity, not from one
  document crowding out the others.

## Limitations

- 20 questions over 3 short documents: enough to catch regressions, too small for statistically meaningful
  comparisons between methods.
- Synthetic documents are cleaner than real PDFs (no multi-column layouts, headers, footnotes or scans).
- Keyword match can accept a wrong answer that happens to contain the number, and reject a correct paraphrase.
- The lexical baseline is a pipeline test, not a quality claim for DocuMind with Gemini.
